# 迭代 I20 开发包 — 朋友修改回流：分享导出 + 队长导入

> 用法：在项目根目录 `D:\AI agent\ZCode data\CS2` 打开新的 ZCode 会话，粘贴下面提示词执行。
> 背景（2026-10-01 用户提出）：发布包发朋友后，朋友也会想录自己常用的道具——「每个人喜欢的
> 道具不同，肯定会有新录入的」。现状：朋友包与自用版同一套 viewer 代码，朋友可以在网页里
> 新增/编辑（存他浏览器的 localStorage 覆盖层 + IndexedDB 图片），但 ①只有他自己看得见；
> ②换浏览器/清缓存就丢；③没法把好东西传回给队长（用户）进大家的册子。
> 方案：不把源文件（data/、tools/）放进朋友包（朋友没有打包工具，改了文件 data.js 也不会
> 重建，反而制造"改了文件不生效"的新坑；且新 zip 一覆盖，文件修改直接丢失）。朋友侧维持
> 浏览器暂存形态，加「📤 分享我的修改」导出一个 JSON 修改包，微信/QQ 发给队长；队长侧
> 「📥 导入朋友的修改」一键收编入库。
> 前置：**I19 已执行完成并验收**（本包依赖 I19 的覆盖层新结构与 rootPerm 三态；执行前先读
> docs/PROGRESS.md 确认，若 I19 未完成则先执行 I19）。

1. ⚙ 设置弹层加按钮「📤 把我的修改分享给队长」：仅当覆盖层有条目暂存或 IndexedDB 有图时

     新增默认勾选、**更新默认不勾**（保守：朋友的改动要队长过目才进库）、新报点默认勾选；
   - 每条显示：标题 + 类型图标 + 起点→目标 + 投法徽章；更新条目附一行要点

     · **status 一律 draft、删除 checked**（铁律：朋友录入 ≠ 已实测，转绿只能队长亲测）；
     · source 写 { kind: "friend", creator: 昵称, url: "" }；

## 给用户的说明（大白话）

**朋友现在就能改，但只有他自己看得见。** 发布包和你的版本是同一套网页，朋友打开后一样能
「新增道具、传图、编辑」——但这些都存在**他自己的浏览器**里：换电脑、清缓存就没了，别人
也看不到，更进不了你下次发的包。

这个迭代给朋友圈加一条「回流」通道，工作流变成：

1. **朋友自己先用**：看到好道具就自己录（存他自己浏览器，随录随看）；
2. **觉得值得共享**：⚙ 设置 → 「📤 把我的修改分享给队长」，下载一个小文件，微信发你；
3. **你收编**：⚙ 设置 → 「📥 导入朋友的修改」，预览勾选 → 一键入库。**入库一律是「待验证」**
   （状态诚实：朋友录的 ≠ 实测过，你亲测后才转绿）；
4. 双击「同步并打包.bat」，下次发的 zip 大家都有这条了。

**为什么不直接让朋友改文件？** 朋友那边没有打包工具，改了源文件页面也不会刷新出来；
而且你下次发新 zip 一覆盖，朋友改的文件就没了。浏览器暂存 + 发修改包给你统一收编，
是最稳也不需要朋友装任何东西的方式。
