## 粘贴提示词

```text
按 AGENTS.md 规范执行查看器小迭代（迭代 I23）：恢复阵营过滤。只改 assets/js/app.js + style.css，
不碰数据文件。先读 init() 顶栏构建与 entryMatch()（可见条目集合的现有过滤管线）。

一、顶栏恢复 全部/T/CT 分段按钮
1. 位置：类型图标过滤之后、搜索框之前（与 I14 之前样式一致）。
2. 语义：
   - 全部 = 不过滤（默认）；
   - T = 显示 side ∈ {T, both} 的条目；
   - CT = 显示 side ∈ {CT, both} 的条目；
   - **side=both 的条目在 T 与 CT 下都显示**（双方通用道具不能被藏掉）。
3. 作用范围（与 I14 类型过滤同一条「可见条目集合」管线，取交集）：
   - 道具列表条目；
   - 战术板地图的报点相关性判断（类型过滤怎么作用于报点，阵营过滤就怎么叠加）；
   - 战术板卡片（tactics 条目自身的 side）。
4. 选择状态仅会话内有效，不持久化（刷新回 全部）。

二、收尾
1. pb build（版本号由 I19 起的自动递增机制处理，无需手改 index.html）。
2. pb lint / pb pack 跑一遍。

红线：不动分拣台（I22）行编辑（行内 side 由地图默认，不加列）；不改数据文件。
验收清单（逐项自检，强刷后）：
- [ ] 顶栏出现 全部/T/CT，默认全部
- [ ] 当前数据下选 CT：能看到 1 颗 CT 回防烟（side=CT）；
      选 T：能看到 T 方条目；side=both 的条目（如有）在 T/CT 下都出现
- [ ] 战术板地图叠加阵营+类型过滤时取交集，报点集合随之正确收窄
- [ ] lint / build / pack 通过；控制台无报错
```
