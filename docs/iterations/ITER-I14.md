按 AGENTS.md 规范执行查看器迭代（迭代 I14）。改 assets/js/app.js + style.css，不碰数据文件。
动手前先读 render()/init() 顶栏构建、calloutMapCard()/refreshEditor() 的报点标签渲染，
以及 style.css 里的 @media (min-aspect-ratio: 1/1) 媒体查询块（本迭代第四项的重点嫌疑）。

一、默认地图 = 炙热沙城，并记住上次选择
1. state.map 初始值：localStorage 记忆的上次选择（key 如 pb-map），无记忆时默认 "de_dust2"。
2. 地图下拉 change 时把选择写入 localStorage；首页/刷新后恢复上次选择。

二、删除顶栏 全部/T/CT 过滤
1. 移除顶栏三个按钮及其事件与样式；条目数据里的 side 字段保留不动（lint 与数据格式不变），
   仅界面不再提供该过滤。
2. 删除后顶栏布局重排：地图下拉 → 类型图标 → 搜索 → 失效也显示 → 同步提示。

三、类型图标过滤作用于战术板地图
1. 语义：烟/闪/火/雷过滤激活时（任一类型被选中），战术板地图只显示「与当前可见条目
   相关」的报点——判断标准：该报点被某条可见条目的 origin / target / spots 命中
   （沿用 originIs/targetIs/spotNameMatch 的既有匹配函数）。
2. 未被命中的报点标签隐藏（不是变暗，直接不渲染）；无任何类型过滤时显示全部报点。
3. 搜索框（state.search）与 钻取状态 与类型过滤叠加时取交集；「失效也显示」开关
   继续只影响条目可见性，进而影响报点的相关性判断。
4. 编辑报点弹窗里的地图不受类型过滤影响（编辑器永远显示全部报点）。

四、修报点标签横竖屏错位（用户实测：同一地图标签位置在竖屏/横屏不一致）
1. 先复现定位：本地起服务开页面，把窗口从横屏拖成竖屏，对比编辑器与报点图卡片上
   同一报点标签相对地图特征的位置。重点嫌疑：style.css 的 @media (min-aspect-ratio: 1/1)
   块内是否有影响 .radar-wrap / .map-wrap / img.radar / .callout-label 尺寸或定位的规则；
   以及标签百分比定位的参照盒（wrap）与 img 实际渲染盒是否一致（img 是否被 max-height/
   object-fit/letterbox 改变了有效盒子）。
2. 修复原则（结构性，不做屏幕方向特判）：报点标签层必须与 img 的渲染盒**严格同盒**——
   在 .radar-wrap 内包一层 .callout-layer（position:absolute; inset 与 img 完全重合），
   标签一律放这层里用 left:u*100%;top:v*100% 定位；wrap 内不得有其他参与高度的内容。
   若发现媒体查询改动了盒子尺寸，删除该规则（缩放/布局不得随屏幕方向变化）。
3. 回归确认：正方形雷达（Dust2/Mirage）与 1:2 拼接雷达（Nuke/Vertigo 上下层）在
   竖屏 1440×2560 与横屏 2560×1440 下，同一报点相对地图特征的相对位置完全一致。

五、收尾
1. index.html 三处 ?v= 递增到 21（当前 20）。
2. pb lint / pb build / pb pack 跑一遍。

红线：side 字段与数据格式保留；类型过滤不得改变道具 Tab 既有行为；
报点数据（u/v）本身不动——错位是渲染层问题，禁止用改坐标的方式"修"。
验收清单（逐项自检，强刷 ?v=21 后）：

- [x] 编辑报点弹窗地图不受类型过滤影响（类型过滤激活时选点弹窗仍全量 60 点）
- [x] Dust2 与 Nuke 拼接图在横/竖屏下报点位置逐点一致（各抽 5 点实测相对坐标逐位相同）

执行说明（2026-10-01）：错位根因不是媒体查询——是报点图卡片与编辑器的 img.radar 一直没有
width:100% 规则（裸 img 固有尺寸 1024/2048px，wrap 盒与 img 渲染盒不一致，标签百分比参照漂移）；
